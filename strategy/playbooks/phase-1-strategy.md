# 第 1 階段手冊 — 策略與架構

> **時長**：5-10 天 | **智能體**：8 個 | **守門人**：工作室製片人 + 現實檢驗者

---

## 目標

定義我們要做什麼、怎麼搭、成功標準是什麼——一行代碼都不寫之前搞定這些。每個架構決策都有記錄，每個功能都排過優先級，每一筆錢都算清楚。

## 前提條件

- [ ] 第 0 階段質量門禁通過（"繼續"決策）
- [ ] 收到第 0 階段交接包
- [ ] 利益相關方在項目範圍上已對齊

## 智能體激活順序

### 第一步：策略定調（第 1-3 天，並行）

#### 工作室製片人 — 策略組合對齊
```
激活工作室製片人，做 [項目] 的策略組合對齊。

輸入：第 0 階段高管摘要 + 市場分析報告
交付要求：
1. 策略組合計劃及項目定位
2. 願景、目標和 ROI 指標
3. 資源配置策略
4. 風險收益評估
5. 成功標準和里程碑定義

對齊目標：組織層面的策略目標
格式：策略組合計劃模板
時間線：3 天
```

#### 品牌守護者 — 品牌識別系統
```
激活品牌守護者，做 [項目] 的品牌識別建設。

輸入：第 0 階段 UX 調研（畫像、旅程圖）
交付要求：
1. 品牌基礎（使命、願景、價值觀、品牌個性）
2. 視覺識別系統（顏色、字體、間距用 CSS 變量）
3. 品牌語調和信息架構
4. Logo 系統規範（如果是新品牌）
5. 品牌使用規範

格式：品牌識別系統文檔
時間線：3 天
```

#### 財務追蹤員 — 預算和資源規劃
```
激活財務追蹤員，做 [項目] 的財務規劃。

輸入：工作室製片人策略計劃 + 第 0 階段技術棧評估
交付要求：
1. 按類別分的完整項目預算
2. 資源成本預測（智能體、基礎設施、工具）
3. ROI 模型及盈虧平衡分析
4. 現金流時間線
5. 財務風險評估及應急儲備

格式：財務計劃 + ROI 預測
時間線：2 天
```

### 第二步：技術架構（第 3-7 天，並行，第一步產出就緒後）

#### UX 架構師 — 技術架構 + UX 基礎
```
激活 UX 架構師，做 [項目] 的技術架構。

輸入：品牌守護者視覺識別 + 第 0 階段 UX 調研
交付要求：
1. CSS 設計系統（變量、token、比例尺）
2. 佈局框架（Grid/Flexbox 模式、響應式斷點）
3. 組件架構（命名規範、層級結構）
4. 信息架構（頁面流程、內容層級）
5. 主題系統（亮色/暗色/跟隨系統切換）
6. 無障礙基礎（WCAG 2.1 AA 基線）

要創建的文件：
- css/design-system.css
- css/layout.css
- css/components.css
- docs/ux-architecture.md

格式：開發者可直接使用的基礎包
時間線：4 天
```

#### 後端架構師 — 系統架構
```
激活後端架構師，做 [項目] 的系統架構。

輸入：第 0 階段技術棧評估 + 合規要求
交付要求：
1. 系統架構文檔
   - 架構模式（微服務/單體/Serverless/混合）
   - 通信模式（REST/GraphQL/gRPC/事件驅動）
   - 數據模式（CQRS/Event Sourcing/CRUD）
2. 數據庫 Schema 設計及索引策略
3. API 設計文檔及版本策略
4. 認證和授權架構
5. 安全架構（縱深防禦）
6. 擴展方案（水平擴展策略）

格式：系統架構文檔
時間線：4 天
```

#### AI 工程師 — ML 架構（如果需要）
```
激活 AI 工程師，做 [項目] 的 ML 系統架構。

輸入：後端架構師系統架構 + 第 0 階段數據審計
交付要求：
1. ML 系統設計
   - 模型選型和訓練策略
   - 數據管道架構
   - 推理策略（實時/批處理/邊緣）
2. AI 倫理和安全框架
3. 模型監控和重訓練計劃
4. 與主應用的集成點
5. ML 基礎設施成本預測

前提：只在項目包含 AI/ML 功能時激活
格式：ML 系統設計文檔
時間線：3 天
```

#### 高級項目經理 — 需求到任務的轉化
```
激活高級項目經理，為 [項目] 創建任務清單。

輸入：全部第 0 階段文檔 + 架構文檔（已有的部分）
交付要求：
1. 完整任務清單
   - 引用需求文檔的原文（不加額外功能）
   - 每個任務有明確的驗收標準
   - 標註任務間的依賴
   - 工作量估算（故事點或小時）
2. 工作分解結構
3. 關鍵路徑識別
4. 實現階段的風險登記表

規則：
- 不要加需求文檔裡沒有的功能
- 引用需求的原文
- 工作量估算要實事求是

格式：帶驗收標準的任務清單
時間線：3 天
```

### 第三步：排優先級（第 7-10 天，串行，第二步完成後）

#### Sprint 排序師 — 功能排序
```
激活 Sprint 排序師，做 [項目] 的待辦排序。

輸入：
- 高級項目經理 → 任務清單
- 後端架構師 → 系統架構
- UX 架構師 → UX 架構
- 財務追蹤員 → 預算框架
- 工作室製片人 → 策略計劃

交付要求：
1. RICE 評分的待辦列表（Reach, Impact, Confidence, Effort）
2. 按速度估算的 Sprint 分配
3. 依賴圖 + 關鍵路徑
4. MoSCoW 分類（Must/Should/Could/Won't）
5. 發佈計劃和里程碑映射

驗證：工作室製片人確認策略對齊
格式：排好序的 Sprint 計劃
時間線：2 天
```

## 質量門禁檢查清單

| # | 標準 | 證據來源 | 狀態 |
|---|------|---------|------|
| 1 | 架構覆蓋 100% 的需求 | 高級項目經理任務清單與架構交叉核對 | |
| 2 | 品牌系統完整（logo、顏色、字體、語調） | 品牌守護者交付物 | |
| 3 | 所有技術組件都有實現路徑 | 後端架構師 + UX 架構師文檔 | |
| 4 | 預算已批准且在約束範圍內 | 財務追蹤員計劃 | |
| 5 | Sprint 計劃基於速度估算、切合實際 | Sprint 排序師待辦列表 | |
| 6 | 安全架構已定義 | 後端架構師安全文檔 | |
| 7 | 合規要求已融入架構 | 法律要求與技術決策的映射 | |

## 門禁決策

**需要雙籤**：工作室製片人（策略層面）+ 現實檢驗者（技術層面）

- **通過**：帶著完整架構包進入第 2 階段
- **修改**：具體事項需要返工（回到對應步驟）
- **重來**：架構有根本性問題（重新走第 1 階段）

## 交接給第 2 階段

```markdown
## 第 1 階段 → 第 2 階段交接包

### 架構包：
1. 策略組合計劃（工作室製片人）
2. 品牌識別系統（品牌守護者）
3. 財務計劃（財務追蹤員）
4. CSS 設計系統 + UX 架構（UX 架構師）
5. 系統架構文檔（後端架構師）
6. ML 系統設計（AI 工程師——如果有的話）
7. 完整任務清單（高級項目經理）
8. 排好序的 Sprint 計劃（Sprint 排序師）

### 給 DevOps 自動化師的：
- 後端架構師的部署架構
- 系統架構中的環境要求
- 基礎設施的監控要求

### 給前端開發者的：
- UX 架構師的 CSS 設計系統
- 品牌守護者的品牌識別
- UX 架構師的組件架構
- 後端架構師的 API 文檔

### 給後端架構師（繼續工作）的：
- 數據庫 Schema 準備好部署
- API 骨架準備好實現
- 認證系統架構已定義
```

*當工作室製片人和現實檢驗者都在架構包上簽字後，第 1 階段結束。*
