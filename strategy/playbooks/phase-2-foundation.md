# 第 2 階段手冊 — 基礎與腳手架

> **時長**：3-5 天 | **智能體**：6 個 | **守門人**：DevOps 自動化師 + 證據收集者

---

## 目標

搭好後續所有工作的技術和運營基礎。先把骨架立起來，再往上加肉。這個階段結束後，每個開發者都有可用的開發環境、可部署的流水線、和可用的設計系統。

## 前提條件

- [ ] 第 1 階段質量門禁通過（架構包已批准）
- [ ] 收到第 1 階段交接包
- [ ] 所有架構文檔已定稿

## 智能體激活順序

### 工作流 A：基礎設施（第 1-3 天，並行）

#### DevOps 自動化師 — CI/CD 流水線 + 基礎設施
```
激活 DevOps 自動化師，為 [項目] 搭建基礎設施。

輸入：後端架構師系統架構 + 部署要求
交付要求：
1. CI/CD 流水線（GitHub Actions / GitLab CI）
   - 安全掃描階段
   - 自動化測試階段
   - 構建和容器化階段
   - 部署階段（藍綠或金絲雀）
   - 自動回滾能力
2. 基礎設施即代碼
   - 環境配置（開發、預發佈、生產）
   - 容器編排配置
   - 網絡和安全配置
3. 環境配置
   - 密鑰管理
   - 環境變量管理
   - 多環境一致性

要創建的文件：
- .github/workflows/ci-cd.yml（或等效配置）
- infrastructure/（Terraform/CDK 模板）
- docker-compose.yml
- Dockerfile

格式：可運行的 CI/CD 流水線 + IaC 模板
時間線：3 天
```

#### 基礎設施運維師 — 雲基礎設施 + 監控
```
激活基礎設施運維師，為 [項目] 搭建監控。

輸入：DevOps 自動化師基礎設施 + 後端架構師架構
交付要求：
1. 雲資源配置
   - 計算、存儲、網絡資源
   - 自動伸縮配置
   - 負載均衡配置
2. 監控體系
   - 應用指標（Prometheus/DataDog）
   - 基礎設施指標
   - 自定義儀表盤（Grafana）
3. 日誌和告警
   - 集中式日誌收集
   - 關鍵閾值的告警規則
   - 值班通知配置
4. 安全加固
   - 防火牆規則
   - SSL/TLS 配置
   - 訪問控制策略

格式：基礎設施就緒報告 + 儀表盤訪問入口
時間線：3 天
```

#### 工作室運營 — 流程搭建
```
激活工作室運營，為 [項目] 搭建流程。

輸入：Sprint 排序師計劃 + 項目牧羊人協調需求
交付要求：
1. Git 工作流
   - 分支策略（GitFlow / 主幹開發）
   - PR 審核流程
   - 合併策略
2. 溝通渠道
   - 團隊頻道搭建
   - 通知路由
   - 狀態更新節奏
3. 文檔模板
   - PR 模板
   - Issue 模板
   - 決策日誌模板
4. 協作工具
   - 項目看板搭建
   - Sprint 追蹤配置

格式：運營手冊
時間線：2 天
```

### 工作流 B：應用基礎（第 1-4 天，並行）

#### 前端開發者 — 項目腳手架 + 組件庫
```
激活前端開發者，為 [項目] 搭建項目腳手架。

輸入：UX 架構師 CSS 設計系統 + 品牌守護者品牌識別
交付要求：
1. 項目腳手架
   - 框架搭建（React/Vue/Angular，按架構定）
   - TypeScript 配置
   - 構建工具（Vite/Webpack/Next.js）
   - 測試框架（Jest/Vitest + Testing Library）
2. 設計系統實現
   - UX 架構師的 CSS 設計 token
   - 基礎組件庫（Button, Input, Card, Layout）
   - 主題系統（亮色/暗色/跟隨系統切換）
   - 響應式工具
3. 應用外殼
   - 路由搭建
   - 佈局組件（Header, Footer, Sidebar）
   - 錯誤邊界實現
   - 加載狀態

要創建的文件：
- src/（應用源碼）
- src/components/（組件庫）
- src/styles/（設計 token）
- src/layouts/（佈局組件）

格式：可運行的應用骨架 + 組件庫
時間線：3 天
```

#### 後端架構師 — 數據庫 + API 基礎
```
激活後端架構師，為 [項目] 搭建 API 基礎。

輸入：系統架構文檔 + 數據庫 Schema 設計
交付要求：
1. 數據庫搭建
   - Schema 部署（遷移腳本）
   - 索引創建
   - 開發用種子數據
   - 連接池配置
2. API 骨架
   - 框架搭建（Express/FastAPI 等）
   - 按架構搭好路由結構
   - 中間件體系（認證、校驗、錯誤處理、CORS）
   - 健康檢查端點
3. 認證系統
   - 認證提供商集成
   - JWT/Session 管理
   - 基於角色的訪問控制骨架
4. 服務通信
   - API 版本管理
   - 請求/響應序列化
   - 錯誤響應標準化

要創建的文件：
- api/ 或 server/（後端源碼）
- migrations/（數據庫遷移）
- docs/api-spec.yaml（OpenAPI 文檔）

格式：可運行的 API 骨架 + 數據庫 + 認證
時間線：4 天
```

#### UX 架構師 — CSS 系統實現
```
激活 UX 架構師，為 [項目] 實現 CSS 系統。

輸入：品牌守護者品牌識別 + 自己第 1 階段的 CSS 設計系統規範
交付要求：
1. 設計 Token 實現
   - CSS 自定義屬性（顏色、字體、間距）
   - 品牌色板 + 語義化命名
   - 響應式字體比例尺
2. 佈局系統
   - 容器系統（響應式斷點）
   - 網格模式（2 欄、3 欄、側邊欄）
   - Flexbox 工具類
3. 主題系統
   - 亮色主題變量
   - 暗色主題變量
   - 系統偏好檢測
   - 主題切換組件
   - 主題間的平滑過渡

要創建/更新的文件：
- css/design-system.css（或框架中的等效文件）
- css/layout.css
- css/components.css
- js/theme-manager.js

格式：已實現的 CSS 設計系統 + 主題切換
時間線：2 天
```

## 驗證檢查點（第 4-5 天）

### 證據收集者驗證
```
激活證據收集者，驗證第 2 階段基礎搭建。

用截圖證據驗證以下項目：
1. CI/CD 流水線成功執行（展示流水線日誌）
2. 應用骨架在瀏覽器中正常加載（桌面端截圖）
3. 應用骨架在手機上正常加載（手機截圖）
4. 主題切換正常工作（亮色 + 暗色截圖）
5. API 健康檢查有響應（curl 輸出）
6. 數據庫可訪問（遷移狀態）
7. 監控儀表盤在線（儀表盤截圖）
8. 組件庫可渲染（組件演示頁面）

格式：證據包 + 截圖
判定：通過 / 不通過，不通過時列出具體問題
```

## 門禁決策

**需要雙籤**：DevOps 自動化師（基礎設施層面）+ 證據收集者（視覺層面）

- **通過**：骨架應用可運行 + 完整 DevOps 流水線 → 激活第 3 階段
- **不通過**：具體的基礎設施或應用問題 → 修復後重新驗證
