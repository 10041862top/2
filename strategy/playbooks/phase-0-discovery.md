# 第 0 階段手冊 — 情報與發現

> **時長**：3-7 天 | **智能體**：6 個 | **守門人**：高管摘要生成器

---

## 目標

在投入資源之前先驗證機會。問題、市場和監管環境沒搞清楚之前不動手。

## 前提條件

- [ ] 有項目簡報或初始概念
- [ ] 確定了利益相關方贊助人
- [ ] 發現階段的預算已批准

## 智能體激活順序

### 第一波：並行啟動（第 1 天）

#### 趨勢研究員 — 市場情報負責人
```
激活趨勢研究員，做 [項目領域] 的市場情報收集。

交付要求：
1. 競爭格局分析（直接 + 間接競爭對手）
2. 市場規模估算：TAM、SAM、SOM 及方法論
3. 趨勢生命週期圖譜：這個市場在採用曲線的什麼位置？
4. 3-6 個月趨勢預測及置信區間
5. 該領域的投融資趨勢

來源：至少 15 個獨立的、經過驗證的來源
格式：策略報告 + 高管摘要
時間線：3 天
```

#### 反饋分析師 — 用戶需求分析
```
激活反饋分析師，做 [項目領域] 的用戶需求分析。

交付要求：
1. 多渠道反饋收集計劃（問卷、訪談、評論、社交媒體）
2. 現有用戶觸點的情感分析
3. 痛點識別和排序（RICE 評分）
4. 功能需求分析及業務價值估算
5. 反饋模式中的流失風險指標

格式：綜合反饋報告 + 優先級矩陣
時間線：3 天
```

#### UX 研究員 — 用戶行為分析
```
激活 UX 研究員，做 [項目領域] 的用戶行為分析。

交付要求：
1. 用戶訪談計劃（5-10 個目標用戶）
2. 用戶畫像構建（3-5 個主要畫像）
3. 主要用戶流程的旅程圖
4. 競品的可用性啟發式評估
5. 有統計驗證的行為洞察

格式：調研發現報告 + 用戶畫像和旅程圖
時間線：5 天
```

### 第二波：並行啟動（第 1 天，與第一波獨立）

#### 數據分析師 — 數據基礎評估
```
激活數據分析師，做 [項目領域] 的數據基礎評估。

交付要求：
1. 現有數據源審計（有哪些可用數據？）
2. 信號識別（我們能測量什麼？）
3. 基線指標建立
4. 數據質量評估及完整性評分
5. 分析基礎設施建議

格式：數據審計報告 + 信號地圖
時間線：2 天
```

#### 法務合規員 — 監管掃描
```
激活法務合規員，做 [項目領域] 的監管掃描。

交付要求：
1. 適用的監管框架（GDPR、CCPA、HIPAA 等）
2. 數據處理要求和約束
3. 目標市場的司法管轄區映射
4. 合規風險評估及嚴重度評級
5. 阻塞性 vs 可管理的合規問題

格式：合規要求矩陣
時間線：3 天
```

#### 工具評估師 — 技術版圖
```
激活工具評估師，做 [項目領域] 的技術版圖評估。

交付要求：
1. 該問題域的技術棧評估
2. 關鍵組件的自建 vs 採購分析
3. 與現有系統的集成可行性
4. 開源 vs 商業方案評估
5. 技術風險評估

格式：技術棧評估 + 推薦矩陣
時間線：2 天
```

## 匯聚點（第 5-7 天）

六個智能體全部交付報告。高管摘要生成器進行綜合：

```
激活高管摘要生成器，綜合第 0 階段的發現。

輸入文檔：
1. 趨勢研究員 → 市場分析報告
2. 反饋分析師 → 綜合反饋報告
3. UX 研究員 → 調研發現報告
4. 數據分析師 → 數據審計報告
5. 法務合規員 → 合規要求矩陣
6. 工具評估師 → 技術棧評估

輸出：高管摘要（不超過 500 字，SCQA 格式）
需要的決策：繼續 / 終止 / 調整方向
包含：量化的市場機會、驗證過的用戶需求、監管路徑、技術可行性
```

## 質量門禁檢查清單

| # | 標準 | 證據來源 | 狀態 |
|---|------|---------|------|
| 1 | 市場機會驗證通過，TAM 超過最低可行閾值 | 趨勢研究員報告 | |
| 2 | 至少 3 個有數據支撐的已驗證用戶痛點 | 反饋分析師 + UX 研究員 | |
| 3 | 沒有阻塞性合規問題 | 法務合規員矩陣 | |
| 4 | 關鍵指標和數據源已確定 | 數據分析師審計 | |
| 5 | 技術棧可行且已評估 | 工具評估師評估 | |
| 6 | 高管摘要已交付，含繼續/終止建議 | 高管摘要生成器 | |

## 門禁決策

- **繼續**：進入第 1 階段 — 策略與架構
- **終止**：歸檔發現，記錄教訓，資源轉向
- **調整方向**：根據發現修改範圍/方向，針對性地重新跑發現
