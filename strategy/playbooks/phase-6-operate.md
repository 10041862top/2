### 第 6 階段的功能開發

新功能走一個壓縮版的 NEXUS 週期：

```
1. Sprint 排序師從待辦列表選功能
2. 合適的開發智能體實現
3. 證據收集者驗證（開發-測試循環）
4. DevOps 自動化師部署（功能開關或直接發佈）
5. 實驗追蹤員監控（適用時做 A/B 測試）
6. 數據分析師衡量效果
7. 反饋分析師收集用戶反應
```

## 事故響應協議

### 嚴重度分級

| 級別 | 定義 | 響應時間 | 決策權 |
|------|------|---------|--------|
| **P0 — 緊急** | 服務掛了、數據丟了、安全事件 | 立即 | 工作室製片人 |
| **P1 — 高** | 主要功能掛了、性能嚴重下降 | < 1 小時 | 項目牧羊人 |
| **P2 — 中** | 次要功能有問題、有臨時方案 | < 4 小時 | 智能體編排者 |
| **P3 — 低** | 樣式問題、小不便 | 下個 Sprint | Sprint 排序師 |

### 事故響應流程

```
發現（基礎設施運維師 或 客服響應者）
    │
    ▼
分診（智能體編排者）
    ├── 確定嚴重度（P0-P3）
    ├── 指派響應團隊
    └── 通知利益相關方
    │
    ▼
響應
    ├── P0：基礎設施運維師 + DevOps 自動化師 + 後端架構師
    ├── P1：相關開發智能體 + DevOps 自動化師
    ├── P2：相關開發智能體
    └── P3：加到 Sprint 待辦列表
    │
    ▼
解決
    ├── 修復已實現並部署
    ├── 證據收集者驗證修復
    └── 基礎設施運維師確認系統穩定
    │
    ▼
事後復盤
    ├── 工作流優化師主持回顧
    ├── 根因分析已記錄
    ├── 預防措施已確定
    └── 流程改進已落實
```

## 增長運營

### 月度增長復盤（增長黑客主導）

```
1. 渠道表現分析
   - 按渠道的獲客（自然、付費、推薦、社交）
   - 按渠道的 CAC
   - 按漏斗階段的轉化率
   - LTV:CAC 比率趨勢

2. 實驗結果
   - 已完成的 A/B 測試及結論
   - 統計顯著性驗證
   - 勝出方案的落地狀態
   - 新實驗管道

3. 留存分析
   - 隊列留存曲線
   - 流失風險識別
   - 召回活動效果
   - 功能採用指標

4. 增長路線圖更新
   - 下月增長實驗
   - 渠道預算重新分配
   - 新渠道探索
   - 病毒係數優化
```

## 財務運營

### 月度財務復盤（財務追蹤員）

```
1. 營收分析
   - MRR/ARR 追蹤
   - 按細分/套餐的營收
   - 擴展營收
   - 流失對營收的影響

2. 成本分析
   - 基礎設施成本
   - 按渠道的營銷支出
   - 團隊/資源成本
   - 工具和服務成本

3. 單位經濟
   - CAC 趨勢
   - LTV 趨勢
   - LTV:CAC 比率
   - 回本週期

4. 預測
   - 營收預測（滾動 3 個月）
   - 成本預測
   - 現金流預測
   - 預算偏差分析
```
