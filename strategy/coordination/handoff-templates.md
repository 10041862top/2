# NEXUS 交接模板

> NEXUS 流水線中所有智能體之間交接的標準化模板。交接規範做好了，就不會丟上下文——這是多智能體協作失敗的頭號原因。

---

## 1. 標準交接模板

用於任何智能體之間的工作轉交。

```markdown
# NEXUS 交接文檔

## 元數據
| 字段 | 值 |
|------|-----|
| **發送方** | [智能體名稱]（[部門]） |
| **接收方** | [智能體名稱]（[部門]） |
| **階段** | 第 [N] 階段 — [階段名稱] |
| **任務引用** | [Sprint 排序師待辦列表中的任務 ID] |
| **優先級** | [緊急 / 高 / 中 / 低] |
| **時間戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 上下文
**項目**：[項目名稱]
**當前狀態**：[到目前為止做了什麼——要具體]
**相關文件**：
- [文件/路徑/1] — [內容說明]
- [文件/路徑/2] — [內容說明]
**依賴**：[這項工作依賴什麼已完成的部分]
**約束**：[技術、時間線或資源約束]

## 交付要求
**需要什麼**：[具體的、可衡量的交付物描述]
**驗收標準**：
- [ ] [標準 1 — 可衡量]
- [ ] [標準 2 — 可衡量]
- [ ] [標準 3 — 可衡量]
**參考材料**：[需求、設計、之前工作的鏈接]

## 質量預期
**必須通過**：[該交付物的具體質量標準]
**需要的證據**：[完成證明長什麼樣]
**下一個接收方**：[誰接收產出，需要什麼格式]
```

## 2. QA 反饋循環 — 通過

當證據收集者或其他 QA 智能體通過一個任務時使用。

```markdown
# NEXUS QA 判定：通過

## 任務
| 字段 | 值 |
|------|-----|
| **任務 ID** | [ID] |
| **任務描述** | [描述] |
| **開發智能體** | [智能體名稱] |
| **QA 智能體** | [智能體名稱] |
| **第幾次** | 第 [N] 次，共 3 次 |
| **時間戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 判定：通過

## 證據
**截圖**：
- 桌面端（1920x1080）：[文件名/路徑]
- 平板（768x1024）：[文件名/路徑]
- 手機（375x667）：[文件名/路徑]

**功能驗證**：
- [x] [驗收標準 1] — 已驗證
- [x] [驗收標準 2] — 已驗證
- [x] [驗收標準 3] — 已驗證

**品牌一致性**：已驗證 — 顏色、字體、間距符合設計系統
**無障礙**：已驗證 — 鍵盤導航、對比度、語義化 HTML
**性能**：[實測加載時間] — 在可接受範圍內

## 備註
[任何觀察、後續可改進的小建議、或值得表揚的地方]

## 下一步行動
→ 智能體編排者：標記任務完成，進入待辦列表中的下一個任務
```

## 3. QA 反饋循環 — 不通過

當證據收集者或其他 QA 智能體打回一個任務時使用。

```markdown
# NEXUS QA 判定：不通過

## 任務
| 字段 | 值 |
|------|-----|
| **任務 ID** | [ID] |
| **任務描述** | [描述] |
| **開發智能體** | [智能體名稱] |
| **QA 智能體** | [智能體名稱] |
| **第幾次** | 第 [N] 次，共 3 次 |
| **時間戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 判定：不通過

## 發現的問題

### 問題 1：[分類] — [嚴重度：緊急/高/中/低]
**描述**：[問題的準確描述]
**預期**：[按驗收標準應該是什麼樣]
**實際**：[實際是什麼樣]
**證據**：[截圖文件名或測試輸出]
**修復指引**：[具體的、可執行的修復說明]
**需要改的文件**：[準確的文件路徑]

### 問題 2：[分類] — [嚴重度]
**描述**：[...]
**預期**：[...]
**實際**：[...]
**證據**：[...]
**修復指引**：[...]
**需要改的文件**：[...]

[所有發現的問題都列出來]

## 驗收標準狀態
- [x] [標準 1] — 通過
- [ ] [標準 2] — 不通過（見問題 1）
- [ ] [標準 3] — 不通過（見問題 2）

## 重試說明
**給開發智能體**：
1. 只修上面列出的問題
2. 不要加新功能或做其他改動
3. 所有問題修完後重新提交 QA
4. 當前是第 [N] 次，最多 3 次

**如果第 3 次還不通過**：任務將升級給智能體編排者
```

## 4. 升級報告

當一個任務超過 3 次重試時使用。

```markdown
# NEXUS 升級報告

## 任務
| 字段 | 值 |
|------|-----|
| **任務 ID** | [ID] |
| **任務描述** | [描述] |
| **開發智能體** | [智能體名稱] |
| **QA 智能體** | [智能體名稱] |
| **重試已用完** | 3/3 |
| **升級給** | [智能體編排者 / 工作室製片人] |
| **時間戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 失敗歷史

### 第 1 次
- **發現的問題**：[摘要]
- **做了什麼修復**：[開發者改了什麼]
- **結果**：不通過 — [為什麼還是沒過]

### 第 2 次
- **發現的問題**：[摘要]
- **做了什麼修復**：[開發者改了什麼]
- **結果**：不通過 — [為什麼還是沒過]

### 第 3 次
- **發現的問題**：[摘要]
- **做了什麼修復**：[開發者改了什麼]
- **結果**：不通過 — [為什麼還是沒過]

## 根因分析
**為什麼任務一直過不了**：[對底層問題的分析]
**系統性問題**：[這是偶發還是有規律？]
**複雜度評估**：[任務本身的範圍定義是否合理？]

## 建議處理方式
- [ ] **重新分配**給別的開發智能體（[建議的智能體]）
- [ ] **拆分**成更小的子任務（[建議的拆分方案]）
- [ ] **換思路**——架構/設計需要調整
- [ ] **接受**當前狀態，記錄已知限制
- [ ] **推遲**到後面的 Sprint

## 影響評估
**阻塞**：[什麼其他任務被這個堵住了]
**時間線影響**：[對整體排期的影響]
**質量影響**：[如果接受當前狀態，有什麼質量上的妥協]

## 需要決策
**決策者**：[智能體編排者 / 工作室製片人]
**截止時間**：[什麼時候需要做決定才不會進一步延誤]
```

| **時間戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 門禁標準結果
| # | 標準 | 閾值 | 結果 | 證據 |
|---|------|------|------|------|

## 6. Sprint 交接

在 Sprint 邊界使用。

```markdown
# NEXUS Sprint 交接

## Sprint 總結
| 字段 | 值 |
|------|-----|
| **Sprint** | [編號] |
| **持續時間** | [開始日期] → [結束日期] |
| **Sprint 目標** | [目標描述] |
| **速度** | [計劃] / [實際] 故事點 |

## 完成狀態
| 任務 ID | 描述 | 狀態 | QA 次數 | 備註 |
|---------|------|------|---------|------|
| [ID] | [描述] | 完成 | [N] | [備註] |
| [ID] | [描述] | 完成 | [N] | [備註] |
| [ID] | [描述] | 順延 | [N] | [原因] |

## 質量指標
- **首次通過率**：[X]%
- **平均重試次數**：[N]
- **完成任務數**：[X/Y]
- **交付故事點**：[N]

## 順延到下一個 Sprint
| 任務 ID | 描述 | 原因 | 優先級 |
|---------|------|------|--------|
| [ID] | [描述] | [為什麼沒完成] | [RICE 分數] |

## 回顧洞察
**做得好的**：[主要成功點]
**可以改進的**：[主要改進點]
**行動項**：[下個 Sprint 的具體改變]

## 下一個 Sprint 預覽
**Sprint 目標**：[擬定目標]
**重點任務**：[最高優先級的事項]
**依賴**：[跨團隊的依賴]
```

## 7. 事故交接

在事故響應期間使用。

```markdown
# NEXUS 事故交接

## 事故
| 字段 | 值 |
|------|-----|
| **嚴重度** | [P0 / P1 / P2 / P3] |
| **發現者** | [智能體或系統] |
| **發現時間** | [時間戳] |
| **負責人** | [智能體名稱] |
| **狀態** | [排查中 / 止血中 / 已解決 / 事後復盤] |

## 描述
**發生了什麼**：[對事故的清楚描述]
**影響範圍**：[誰/什麼受影響，影響多嚴重]
**時間線**：
- [HH:MM] — [事件]
- [HH:MM] — [事件]
- [HH:MM] — [事件]

## 當前狀態
**受影響的系統**：[列表]
**有沒有臨時方案**：[有/沒有——有的話描述一下]
**預計修復時間**：[估計]

## 已採取的措施
1. [做了什麼，結果是什麼]
2. [做了什麼，結果是什麼]

## 交接上下文
**給下一位響應人**：
- [試過什麼了]
- [還沒試什麼]
- [懷疑的根因]
- [要查的相關日誌/指標]

## 利益相關方通知
**最近一次更新**：[時間戳]
**下次更新時間**：[時間戳]
**通知渠道**：[更新發布在哪]
```

## 使用指南

| 場景 | 用哪個模板 |
|------|-----------|
| 把工作交給另一個智能體 | 標準交接（#1） |
| QA 通過一個任務 | QA 通過（#2） |
| QA 打回一個任務 | QA 不通過（#3） |
| 任務超過 3 次重試 | 升級報告（#4） |
| 階段之間切換 | 階段門禁交接（#5） |
| Sprint 結束 | Sprint 交接（#6） |
| 系統事故 | 事故交接（#7） |
