# 操作手冊：企業級功能開發

> **模式**：NEXUS-Sprint | **時長**：6-12 周 | **智能體**：20-30

---

## 場景

你要在一個現有的企業級產品上加一個大功能。合規、安全、質量門禁沒有商量餘地。多方利益相關方需要對齊。功能必須和現有系統無縫集成。

## 執行計劃

### 第 1 階段：需求與架構（第 1-2 周）

```
第 1 周：利益相關方對齊
├── 項目牧羊人 → 利益相關方分析 + 溝通計劃
├── UX 研究員 → 功能需求的用戶調研
├── 法務合規員 → 合規要求掃描
├── 高級項目經理 → 需求轉任務
└── 財務追蹤員 → 預算框架

第 2 周：技術架構
├── UX 架構師 → UX 基礎 + 組件架構
├── 後端架構師 → 系統架構 + 集成方案
├── UI 設計師 → 組件設計 + 設計系統更新
├── Sprint 排序師 → RICE 評分的待辦列表
├── 品牌守護者 → 品牌影響評估
└── 質量門禁：架構評審（項目牧羊人 + 現實檢驗者）
```

### 第 2 階段：基礎搭建（第 3 周）

```
├── DevOps 自動化師 → 功能分支流水線 + 功能開關
├── 前端開發者 → 組件腳手架
├── 後端架構師 → API 骨架 + 數據庫遷移
├── 基礎設施運維師 → 預發佈環境搭建
└── 質量門禁：基礎驗證（證據收集者）
```

### 第 3 階段：構建（第 4-9 周）

```
Sprint 1-3（第 4-9 周）：
├── 智能體編排者 → 開發-測試循環管理
├── 前端開發者 → UI 實現（逐任務）
├── 後端架構師 → API 實現（逐任務）
├── 高級開發者 → 複雜/高級功能
├── 證據收集者 → 每個任務都 QA（截圖）
├── API 測試員 → 每個 API 任務都驗證端點
├── 實驗追蹤員 → 關鍵功能搭 A/B 測試
│
├── 雙週：
│   ├── 項目牧羊人 → 利益相關方狀態更新
│   ├── 高管摘要生成器 → 高管簡報
│   └── 財務追蹤員 → 預算追蹤
│
└── Sprint 回顧 + 利益相關方演示
```

### 第 4 階段：加固（第 10-11 周）

```
第 10 周：證據收集
├── 證據收集者 → 全量截圖套件
├── API 測試員 → 完整迴歸套件
├── 性能基準師 → 10 倍流量壓力測試
├── 法務合規員 → 最終合規審計
├── 測試結果分析師 → 質量指標儀表盤
└── 基礎設施運維師 → 生產就緒檢查

第 11 周：最終判定
├── 現實檢驗者 → 集成測試（默認：需要改進）
├── 需要的話修一修（2-3 天）
├── 重新驗證
└── 高管摘要生成器 → 上線/不上線建議
```

### 第 5 階段：灰度上線（第 12 周）

```
├── DevOps 自動化師 → 金絲雀部署（5% → 25% → 100%）
├── 基礎設施運維師 → 實時監控
├── 數據分析師 → 功能採用率追蹤
├── 客服響應者 → 新功能用戶支持
├── 反饋分析師 → 早期反饋收集
└── 高管摘要生成器 → 上線報告
```

## 利益相關方溝通節奏

| 受眾 | 頻率 | 智能體 | 格式 |
|------|------|--------|------|
| 高管贊助人 | 雙週 | 高管摘要生成器 | SCQA 摘要（不超過 500 字） |
| 產品團隊 | 每週 | 項目牧羊人 | 狀態報告 |
| 工程團隊 | 每日 | 智能體編排者 | 流水線狀態 |
| 合規團隊 | 每月 | 法務合規員 | 合規狀態 |
| 財務 | 每月 | 財務追蹤員 | 預算報告 |

## 質量要求

| 要求 | 閾值 | 驗證方 |
|------|------|--------|
| 代碼覆蓋率 | > 80% | 測試結果分析師 |
| API 響應時間 | P95 < 200ms | 性能基準師 |
| 無障礙 | WCAG 2.1 AA | 證據收集者 |
| 安全 | 零嚴重漏洞 | 法務合規員 |
| 品牌一致性 | 95%+ 合規 | 品牌守護者 |
| 需求合規 | 100% | 現實檢驗者 |
| 承壓能力 | 當前流量的 10 倍 | 性能基準師 |

## 風險管理

| 風險 | 概率 | 影響 | 緩解措施 | 負責人 |
|------|------|------|---------|--------|
| 集成複雜度 | 高 | 高 | 儘早做集成測試，每個 Sprint 都跑 API 測試員 | 後端架構師 |
| 範圍蔓延 | 中 | 高 | Sprint 排序師用 MoSCoW 管控，項目牧羊人管理變更 | Sprint 排序師 |
| 合規問題 | 中 | 緊急 | 法務合規員從第 1 天就參與 | 法務合規員 |
| 性能退化 | 中 | 高 | 每個 Sprint 都跑性能基準師測試 | 性能基準師 |
| 利益相關方不對齊 | 低 | 高 | 雙週高管簡報，項目牧羊人協調 | 項目牧羊人 |
